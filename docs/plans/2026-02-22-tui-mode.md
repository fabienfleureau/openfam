# Plan: TUI (Text User Interface) Mode

**Date:** 2026-02-22
**Status:** Proposed
**Scope:** Interactive terminal dashboard for OpenFAM CLI.

## Overview

Provide a rich, interactive terminal experience for managing the family network without requiring the web dashboard. This is useful for advanced users and quick adjustments.

## 1. Tech Stack

- **Framework:** `ink` (React-based CLI UI)
- **State Management:** React Hooks (useState, useEffect)
- **Icons/Styling:** `figures`, `chalk`, `ink-box`, `ink-spinner`
- **Networking:** Existing `RouterService` (SSH)

## 2. UI Architecture

### Components
- **Layout:** Sidebar (Navigation) + Main Content Area + Status Bar (Router Connectivity).
- **Dashboard:** Summary view (online devices, active profile).
- **Profile Manager:** Interactive list of profiles with edit/delete actions.
- **Device List:** Real-time list of connected devices (using `devices scan`).
- **Log Viewer:** Streaming view of `agent.sh` logs.

### Navigation (Tabs)
1. `[D]` Dashboard
2. `[P]` Profiles
3. `[V]` Devices
4. `[L]` Logs
5. `[S]` Settings

## 3. Implementation Steps

### Phase 1: Foundation
- [ ] Add `ink` and `react` dependencies to `openfam-cli`.
- [ ] Implement `openfam ui` command wrapper.
- [ ] Create basic layout with navigation handling.

### Phase 2: Core Views
- [ ] **Status View:** Fetch router status via SSH and display in real-time.
- [ ] **Profile View:** Fetch JSON config and render as an interactive list.
- [ ] **Log View:** Implement `tail -f` equivalent over SSH within the UI.

### Phase 3: Interactive Actions
- [ ] Add "Toggle Profile" functionality.
- [ ] Add "Assign Device to Profile" interactive picker.
- [ ] Add "Force Agent Run" button.

## 4. Design Principles

- **Keyboard First:** All actions should be mapped to single-key shortcuts (e.g., `q` to quit, `r` to refresh).
- **Non-Blocking:** Network requests must happen in the background without freezing the UI.
- **Responsive:** UI should adapt (or gracefully degrade) to different terminal sizes.
- **Error Boundaries:** SSH connection drops should be handled with a "Reconnecting..." overlay.

## 5. Performance Considerations

- Minimize the number of SSH commands sent.
- Cache the JSON configuration locally after the first fetch.
- Use `tail -n 20` for logs instead of fetching the whole file.
